# App Privacy answers (App Store Connect)

Crucible has no third-party analytics, no ads and no sign-up. It talks to plex.tv and the user's Plex server, from version 2.4 keeps Crucible Pro purchases in Midgar's purchase ledger with an anonymous Midgar ID (MidgarKit), and from version 2.10 sends what a viewer asks Crucible's AI (What to Watch, Write a Recap) to Midgar's model service, which passes it to Anthropic to answer. This replaces the earlier label, "Purchases, Purchase History, not linked", which held while RevenueCat checked purchases with a random app user ID. From the first version released after 2026-11-27 the iPhone and Apple TV apps also send Midgar's anonymous usage counts and crash reports (Lifestream, MidgarKit's signals), which the Usage Counts switch in Settings › Privacy & Data turns off.

| Data type (Apple) | Linked | Tracking | Purpose | What it is in Crucible |
| --- | --- | --- | --- | --- |
| Identifiers, User ID | Yes | No | App Functionality | The random Midgar ID, sent as the sign-in token to `api.midgarcorp.cc` for the purchase ledger and carried by purchases as Apple's app account token |
| Identifiers, Device ID | Yes | No | App Functionality | MidgarKit's App Attest key id on iPhone, stored with the Midgar ID when it is created or joined; no advertising or vendor identifier |
| Purchases, Purchase History | Yes | No | App Functionality | The App Store transactions of Crucible Pro (lifetime, yearly), sent to the Midgar ledger with the Midgar ID |
| Usage Data, Product Interaction | Yes | No | App Functionality | From 2.9, only once the viewer connects Trakt: what they play (scrobbles), mark watched and check in to, sent to their Trakt account by title id. From 2.10, only when the viewer asks Crucible's AI: for What to Watch the titles of their films and series with year, genres, length, ratings and watched state, and for Write a Recap the series and the descriptions of the episodes they finished, sent to `api.midgarcorp.cc` with the Midgar ID as sign-in and passed on to Anthropic without it; Midgar stores a count per day, not the content, and Anthropic deletes it within 30 days. From the first version released after 2026-11-27 (Analytics): the anonymous counts MidgarKit's signals send to `api.midgarcorp.cc/v1/signals` with no Midgar ID, device identifier or `Authorization` header: that the app was active on a day, week and month, the Pro screen shown and where from, which of its features are used in a week, whether the install is free, on a trial, paying or lapsed, how soon after installing the first film or episode played and, held back for hours and counted one fact at a time, what led up to a purchase or to a renewal being turned off. Each is a word from a fixed list; none carries an identifier, so these counts are not linked, but the row stays linked for Trakt and the AI |
| Search History | Yes | No | App Functionality | From 2.10, only when the viewer asks What to Watch: the sentence they typed or dictated, sent and handled as the row above |
| User Content, Other User Content | Yes | No | App Functionality | From 2.9, only once the viewer connects Trakt: the ratings they give titles, sent to their Trakt account |
| Diagnostics, Crash Data | No | No | App Functionality | From the first version released after 2026-11-27, on iPhone: when the app crashes or freezes, MidgarKit sends one crash card to `api.midgarcorp.cc/v1/signals/diagnostics`: the kind of fault, the code addresses on the stack, the last screens shown (from a fixed list), the app build, the OS version and the device model, at most five a day. It holds no title, library or server name, no file path, no Midgar ID and no device identifier, and the request carries no `Authorization` header. A TestFlight or development build sends none, and Usage Counts off stops it. Apple TV has no MetricKit and sends no card |
| Diagnostics, Performance Data | No | No | App Functionality | From the same version, on iPhone: daily numbers from MetricKit, sent as anonymous counts through the same signals client: how long the app takes to start, how long it stopped responding, the memory it used and how often the system ended it. Usage Counts turns them off too |

Everything else (contact info, location, other diagnostic data, other usage data and user content) is not collected. Nothing reaches Crucible's AI unless the viewer asks, and the built-in demo never asks. Seerr is the viewer's own server, like Plex, so the titles they request through it are not collected. The diagnostic log stays on the device unless the user exports it; MetricKit's full reports never leave it.

`store/app-privacy.json` is the machine-readable form for `asc web privacy plan`, `apply` and `publish`. It matches the `PrivacyInfo.xcprivacy` files of both apps.
