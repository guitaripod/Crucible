# Crucible for Apple TV: Xcode project and simulator toolchain

The tvOS app is an Xcode project generated by XcodeGen (`tv/project.yml`) around the SwiftPM package at the repo root. It is built, installed, driven and screenshotted on the Mac's Apple TV simulator from the Linux box with `tv/scripts/tv.sh`.

| Target | What it is |
| --- | --- |
| `CrucibleTVApp` | The app: product `Crucible`, bundle id `com.guitaripod.crucible`, module `CrucibleTVApp`. `tv/App/Entry.swift` installs the RevenueCat store for Crucible Pro and the built-in demo library (package products `CrucibleCore`, `CrucibleStore` and `CrucibleDemo`) and then starts `UIApplicationMain` with `TVAppDelegate` from the package product `CrucibleTV`. |
| `CrucibleTVTopShelf` | Top Shelf extension (`com.guitaripod.crucible.topshelf`). `tv/TopShelf/ContentProvider.swift` subclasses `TopShelfProvider` from the package product `CrucibleTopShelf`. |
| `CrucibleTVUITests` | XCUITest bundle (`tv/UITests`) that drives the app through the real focus engine with `XCUIRemote`. |

`Entry.swift` uses `package` API of `CrucibleCore` and `CrucibleStore`, so the app target is compiled with `-package-name <name>`: SwiftPM names a local package after the lowercased directory that holds `Package.swift`, and `project.yml` takes the name from `CRUCIBLE_PACKAGE_NAME`, which `tv.sh generate` and `device-build.sh` set from the checkout's directory. Running `xcodegen` by hand needs the same variable (the root README has the command).

The generated `tv/CrucibleTV.xcodeproj`, `tv/Generated/` (Info.plists and entitlements), `tv/.gen-hash` and `tv/out/` are git-ignored.

## Prerequisites

- `ssh mac` works without a prompt (Mac with Xcode 27, the tvOS 26.5 simulator runtime, `xcodegen` in `/opt/homebrew/bin`). Override the host with `MAC=<ssh host>`.
- Linux: `rsync`, `python3`. `python3 tv/scripts/make-assets.py` additionally needs Pillow and numpy.

## Commands

Always set `NAME=<id>`; it keeps parallel agents apart. It selects the remote checkout (`~/Dev/ios/$NAME`), its DerivedData (`.dd-tvapp`), the simulator `CrucibleTV-$NAME` (Apple TV 4K 3rd generation at 1080p, tvOS 26.5) and the mock server port (`32400 + cksum(NAME) % 500`, override with `MOCK_PORT`).

```
NAME=x tv/scripts/tv.sh generate        sync, xcodegen (skipped when project.yml and the tv/ file list are unchanged)
NAME=x tv/scripts/tv.sh build           generate + xcodebuild; prints the .app path
NAME=x tv/scripts/tv.sh sim-up          create/boot the simulator, print its UDID
NAME=x tv/scripts/tv.sh sim-down [--delete]
NAME=x tv/scripts/tv.sh mock-up         start the mock Plex server on the Mac, print its URL
NAME=x tv/scripts/tv.sh mock-down
NAME=x tv/scripts/tv.sh run [VAR=value ...]   build, install, launch; prints the PID
NAME=x tv/scripts/tv.sh shot <name>     simulator screenshot to tv/out/<name>.png
NAME=x tv/scripts/tv.sh uitest [-only TourTests/testEveryTabShowsItsScreen]
NAME=x tv/scripts/tv.sh logs            tv/out/crucible.log from the app's data container, plus its tail
NAME=x tv/scripts/tv.sh reset           uninstall the app and wipe its data, keep the simulator
```

Each phase prints one line with its elapsed seconds. Build and test logs stay on the Mac in `~/Dev/ios/$NAME/.tvlogs/` (`build.log`, `uitest.log`, `uitest.xcresult`); the command prints only errors and the result lines.

`run` launches with `SIMCTL_CHILD_CRUCIBLE_MOCK=http://127.0.0.1:<port>` when the mock answers (the simulator shares the Mac's network, so loopback works). Extra `VAR=value` arguments become `SIMCTL_CHILD_VAR`. `scripts/mac.sh` is unaffected: it syncs and builds the package schemes `Crucible` and `CrucibleTV` without this project.

## Mock server

`mock-up` rsyncs `marketing/mock` to `~/Dev/ios/$NAME-mock/` (the git-ignored `assets/` are shared in `~/Dev/ios/_mock-assets` and symlinked), starts `server.py` detached and waits for `/identity`. `mock-down` kills only the instance recorded for that port. Environment passed through to the server: `MOCK_LATENCY_MS` (delay every response), `MOCK_PIN_POLLS` (polls before a plex.tv pin returns its token, default 3), `MOCK_HIDDEN_SECTIONS`, `MOCK_HOME_NO_CONTINUE=1` (the Continue Watching hub comes back empty, so Up Next is Home's first rail), `MOCK_LIBRARY_PAD=<n>` (grow the Movies library to n numbered items so pagination and the A-Z jump have something to do), `MOCK_SLOW_HISTORY_SECTIONS=<ids>` with `MOCK_SLOW_HISTORY_MS=<ms>` (delay the watch-history reply of those sections; the id `all` also delays the unscoped history requests that Statistics syncs with), `MOCK_FAIL_SECTIONS=<ids>` (HTTP 404 for those sections' item listings). `MOCK_FAIL_SEARCH=1`, `MOCK_FAIL_GENRE=1` and `MOCK_FAIL_WATCHED=1` (HTTP 404 for `/hubs/search`, genre-filtered listings and the scrobble/unscrobble calls). The server also honours the `unwatched=1` and `inProgress=1` listing filters.

Tests do not depend on how the mock was started or on what an earlier test did: every test class derives from `TVTestCase`, whose class-level setUp calls `GET /mock/reset` (a fresh library and history, no runtime settings, flags and plex.tv switches at their defaults), and `TVTest.fetch(_:)` is the only way tests call the mock (blocking URL loads are refused by `tv.sh uitest`). `GET /mock/env?MOCK_NO_HISTORY=1&...` overrides a `MOCK_*` setting at runtime (`reset=1` returns all of them to what the process was started with; "0" switches a flag or number off), and `TVTest.launch(mock: ["MOCK_NO_HISTORY": "1"])` resets the mock to its defaults on every launch and then applies the settings, so each test states the server it needs and never inherits an earlier test's. Other runtime switches keep their own endpoints: `/mock/flags` (playback and latency), `/mock/hubs`, `/mock/plextv-config`, `/mock/detail-reset`, `/mock/requests?contains=` (a request counter).

The server also answers the plex.tv surface the tvOS sign-in uses: `POST /api/v2/pins`, `GET /api/v2/pins/{id}`, `GET /api/v2/resources`, `GET /api/v2/user`, and `GET /mock/approve?code=...` to approve a pin immediately.

## UI tests and screenshots

`uitest` runs `xcodebuild test` on the NAME simulator, then exports every attachment of the `.xcresult` (`xcrun xcresulttool export attachments`) to `tv/out/ui/<Class.test>/<attachment-name>.png` and lists them. A test takes a screenshot with `TVTest.capture("name", in: self)`, which attaches `XCUIScreen.main.screenshot()` with lifetime `keepAlways`.

- `Remote` (in `tv/UITests/TVTestSupport.swift`) wraps `XCUIRemote.shared`: `press(.up/.down/.left/.right/.select/.menu/.playPause)` and `longPress(_:duration:)`.
- `TVTest.waitForFocus(on:identifier:)` waits for an element's `hasFocus`; `TVTest.settle(_:)` pauses.
- `TVTest.launch()` starts the app with `CRUCIBLE_UITEST=1`. `SIMCTL_CHILD_*` does not reach UI-test launches, so `uitest` exports `TEST_RUNNER_CRUCIBLE_MOCK` (when the mock is running); `xcodebuild` strips the prefix for the test runner and `launch()` forwards `CRUCIBLE_MOCK` and `CRUCIBLE_PLEXTV` into `launchEnvironment`.

## Crucible Pro

Crucible Pro is sold through RevenueCat (`Sources/CrucibleStore`). `Entry.swift` configures the SDK and installs `RevenueCatProAccess` before the first screen; DEBUG runs with `CRUCIBLE_MOCK`, `CRUCIBLE_UITEST` or `CRUCIBLE_PRO` set skip that, so the simulator never talks to the App Store. The scene coordinator then calls `ProAccess.shared.configureForLaunch(store: nil)` (a DEBUG launch takes the scripted store when `CRUCIBLE_PRO` is set; without it the app is a source build: unlocked, no locks, no Pro row), sets the paywall presenter and refreshes the status when the app comes to the front.

- `CRUCIBLE_PRO=free|lifetime|annual|trial` is the status the app starts with. `CRUCIBLE_PRO_STORE=ok|cancel|pending|fail|offline|empty` is how the store answers (`fail`, `offline` and `empty` fail to load the offers, so the paywall shows its unavailable state; a failed purchase cannot be scripted, a failed restore can with `CRUCIBLE_PRO_RESTORE=fail`). `CRUCIBLE_PRO_RESTORE=found|none|fail`, `CRUCIBLE_PRO_TRIAL=0` (no free trial on the annual offer) and `CRUCIBLE_PRO_DELAY_MS` (400 by default; raise it to watch the busy state) complete the script. `TVTest.launch(extraEnvironment:)` passes them.
- The paywall (`Sources/CrucibleTV/Pro`) is a full-screen modal over whatever is on screen; Statistics ranges beyond Week, the Libraries filter and Top Shelf are the Apple TV's Pro features. Free installs publish no Top Shelf content.
- The Top Shelf is a full-screen carousel (`.details`) of Continue Watching then Up Next: title, show/episode line, synopsis, 1920×1080 and 3840×2160 artwork, and Play / More Info. The app writes the snapshot to `Library/Caches/topshelf.json` in the App Group (tvOS denies writes at the container root, and `TopShelfStore` falls back there for older snapshots), the extension writes `topshelf-read.json` after each load, and You → Settings → Diagnostics shows "Top Shelf" (what was written) and "Top Shelf read" (what the extension saw) plus whether the launch was granted the App Group.
- `tv/UITests/ProTests.swift` covers the locks, the paywall in every phase, purchase, restore and the Pro screen. `NAME=x tv/scripts/tv.sh uitest -only ProTests`.

## Demo

The Welcome screen offers "Try the demo" (`DemoMode`, Core) when the build carries `CrucibleDemo`, the fictional library served from inside the app. A DEBUG launch with `CRUCIBLE_DEMO_URL=<running mock server>` installs `DemoMockProvider` instead. The tvOS side lives in `Sources/CrucibleTV/Demo`: the full-screen intro (once per demo session), the "Demo library" row at the top of You, the tour screen (`Show me` per step, Connect your Plex server, See Crucible Pro, Leave the Demo), the finale (once, never over the player or another presented screen) and `TVAppCoordinator+Demo`. The launch gate awaits `DemoMode.resume()` before it decides what to show. While the demo runs every feature gate reads `ProAccess.hasFullAccess` (no locks), the Top Shelf is kept empty, and Settings hides Server & Connection and replaces Sign Out with Leave the Demo.

`tv/UITests/DemoTests.swift` launches without `CRUCIBLE_MOCK` and runs the in-app library; `CRUCIBLE_DEMO_VIA_MOCK=1` points the demo at the mock server instead. `NAME=x tv/scripts/tv.sh uitest -only DemoTests`.

## Brand assets

`python3 tv/scripts/make-assets.py [--preview]` regenerates `tv/Resources/Assets.xcassets`: the layered app icon (`App Icon - Large` 1280x768 and `App Icon - Small` 400x240 @1x/@2x, each with Back/Middle/Front layers; the back layer is opaque, the glow and the crystal are separate transparent layers), the two Top Shelf images (1920x720 and 2320x720, @1x/@2x), `AccentColor` (#FF9F0A) and `LaunchBackground` (#181818). `--preview` writes composites and a parallax contact sheet to `tv/out/assets-preview/`. Check what ends up in the app with `xcrun assetutil --info <app>/Assets.car` on the Mac; the simulator build keeps only the Small icon stack, `xcrun actool tv/Resources/Assets.xcassets --compile <dir> --platform appletvos --minimum-deployment-target 17.0 --target-device tv --app-icon "App Icon & Top Shelf Image" --accent-color AccentColor --output-partial-info-plist <dir>/partial.plist` also compiles the Large (App Store) stack.

## Real Apple TV

`scripts/install-tv.sh` builds a Release device variant on the Mac, signs it with a development profile, installs it on the paired Apple TV with `devicectl`, launches it and checks that the Apple TV reports the build number it just compiled (`CURRENT_PROJECT_VERSION` is the build time, `yyyyMMddHHmm`).

```
scripts/install-tv.sh            build, sign, install, launch, confirm the installed build
scripts/install-tv.sh build      build and sign only (no Apple TV needed); prints the .app path
scripts/install-tv.sh check      compile the device variant for tvOS without signing (no Apple TV needed)
scripts/install-tv.sh logs       tv/out/crucible-device.log from the app's data container, plus its tail
scripts/install-tv.sh devices    the Apple TVs the Mac knows and whether each is paired
scripts/install-tv.sh pair       pair the Apple TV with the Mac from the terminal
```

`TV_DEVICE=<name|identifier|UDID>` picks one when several are paired; `NAME` and `MAC` work as for `tv.sh` (the remote checkout defaults to `~/Dev/ios/CrucibleTVDevice`).

- `tv/scripts/device-spec.py` derives `tv/Generated/project.device.yml` from `project.yml`: the app target only (no Top Shelf extension, UI tests or App Group entitlement, because the profile has none), manual signing scoped to `sdk=appletvos*`, and the bundle id, team and certificate read from the profile so they cannot drift. XcodeGen writes `tv/CrucibleTVDevice.xcodeproj` (git-ignored) next to `CrucibleTV.xcodeproj`.
- `tv/scripts/device-build.sh` runs on the Mac. An ssh shell cannot unlock the login keychain (`codesign` fails with `errSecInternalComponent`), so a signed build imports `~/.config/midgar/signing/midgar_distribution.p12` (it also holds the Apple Development identity) into a temporary keychain, puts it first in the search list, signs and removes it again. It refuses to build when the paired Apple TV's UDID is not in the profile, and verifies the signature and the embedded profile afterwards.
- The profile is `~/.config/midgar/signing/crucible-tvos-dev-2026.mobileprovision`, a `TVOS_APP_DEVELOPMENT` profile for the explicit App ID `XTL-A5EBDAB5.com.guitaripod.crucible` (the id xtool registered for the iPhone development build, so the App Store id `com.guitaripod.crucible` stays untouched) with the Apple Development certificate and every Apple TV that should run the build. It expires on 2027-10-12.
- The device build leaves out Top Shelf: the profile carries no App Group, so `TopShelfStore` finds no container, logs it and skips the snapshot. Turning it on needs the App Group `group.com.guitaripod.crucible` created and assigned to both App IDs in the developer portal (the public API cannot; `asc web app-groups` with an Account Holder or Admin web session can), profiles for the app and the extension, and the extension and entitlements restored in the device spec.
- To see the Top Shelf on the Apple TV, build the full `tv/project.yml` for the device with manual signing against the two App Group development profiles — `Crucible tvOS Dev App Group` (`com.guitaripod.crucible`) and `Crucible Top Shelf Dev App Group` (`com.guitaripod.crucible.topshelf`), both on `P4DQK6SRKR`, containing the Apple TV and `group.com.guitaripod.crucible`. Signing with the plain App IDs replaces the TestFlight install and keeps its data. Then press Home and focus Crucible: the extension runs, writes `topshelf-read.json` beside `Library/Caches/topshelf.json`, and You → Settings → Diagnostics shows both lines plus whether the container was found.
- Release has no DEBUG hooks (`CRUCIBLE_MOCK`, `CRUCIBLE_MODEL_IDENTIFIER`, `CRUCIBLE_STYLE`, `CRUCIBLE_OPEN_LINK`): the device runs the app the way a user would, with the Liquid Glass gate decided by the real tvOS version and hardware.

Pair the Apple TV with the Mac once: on the Apple TV open Settings > Remotes and Devices > Remote App and Devices and leave the screen open, run `scripts/install-tv.sh pair` and type the code the Apple TV shows (it asks again with a fresh code when one is wrong or has expired; a pairing attempt that cannot read a code from stdin burns the one the TV is showing). The Xcode route works too: Window > Devices and Simulators > +, choose the Apple TV, enter the code. `pair` runs `devicectl manage pair` over `ssh -tt`, because `devicectl` prompts for the code on a terminal and buffers its output without one. tvOS has no Developer Mode. `scripts/install-tv.sh devices` then lists the Apple TV as paired; its device JSON has no `reality` field, which is how a real Apple TV differs from a simulated one.

Make the profile again (a new Apple TV, or a year later) on the Mac, with the ASC credentials sourced from `~/.config/midgar/credentials.env`:

```
asc devices list --output table                      the Apple TV's UDID must be registered (asc devices register)
asc profiles create --name "Crucible tvOS Dev" --profile-type TVOS_APP_DEVELOPMENT \
  --bundle <bundle-id resource> --certificate <Apple Development cert> --device <id>,<id>
asc profiles download --id <profile id> --output ~/.config/midgar/signing/crucible-tvos-dev-2026.mobileprovision
```

## Simulator limits

- `TV_RUNTIME=com.apple.CoreSimulator.SimRuntime.tvOS-26-0` (or `-26-5`, `-27-0`) runs the commands on another installed runtime, and `TV_SIM_TYPE=<SimDeviceType id>` on another device type. A simulator is created once per `NAME`, so `sim-down --delete` before switching runtime or device type.
- tvOS 26.0 hangs on 1080p (1x) screens. Moving focus from the keyboard into the Search results makes UIKit's search header collapse (`_UISearchControllerATVSearchBarAnimatorLegacy`) lay out forever: the keyboard container is scaled to 1 pt tall (`UIKBFocusVCView`, bounds 66 pt) and its rounded frame grows by one point per layout pass, so the main thread sits at 100% CPU for minutes and every XCUITest query fails with "Timed out while evaluating UI query". The same hang reproduces in a bare `UISearchController` with a plain vertically scrolling `UICollectionView`, and it does not occur on a 4K (2x) simulator or on tvOS 26.5 and 27.0, so it is not an app bug. `tv.sh` therefore uses the 4K device type when `TV_RUNTIME` is the tvOS 26.0 runtime; run 26.0 on `Apple-TV-4K-3rd-generation-1080p` only to reproduce it.
- Top Shelf renders only on the real Home screen; the simulator can build and install the extension but cannot show it.
- No HDR and no Match Content (display criteria) in the simulator; the glass rendering is the simulator's, not a specific Apple TV model's.
- Scripted remote input exists only through `XCUIRemote` in UI tests.
- Screenshots come from `simctl io` and from XCUITest at 1920x1080; the focus engine is real, but there is no Siri or Home-button behaviour.
